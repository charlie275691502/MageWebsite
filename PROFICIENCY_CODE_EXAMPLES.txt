PROFICIENCY SYSTEM - CODE FLOW EXAMPLES
========================================

EXAMPLE 1: THUNDER SPELL WITH LV5 PROFICIENCY
----------------------------------------------
Scenario: Player with Thunder Lv5 casts damage spell with Thunder requirement

Flow:
1. play_spell_card() extracts spell requirements -> enchantments = [Thunder]
2. execute_spell_effect() calls apply_effect() with enchantments
3. apply_effect() routes to apply_damage_effect()
4. apply_damage_effect() loops through enchantments:
   if Thunder: base_damage += 1 (Lv3)
   if Thunder: base_damage += 2 (Lv5, total +3)
5. Damage applied: 10 base -> 13 total

Key: enchantments vector carries attribute type through effect chain


EXAMPLE 2: FIRE ATTRIBUTE BOLT
-------------------------------
Scenario: Player with Fire Lv3 casts fire attribute bolt

Flow:
1. play_attribute_bolt(card, Fire) manually creates enchantments = [Fire]
2. Calls apply_effect() with IncreaseDamage(0)
3. IncreaseDamage(0) becomes: damage = fire_level + 0 = 3
4. apply_damage_effect() sees Fire in enchantments:
   base_damage += 1 (Fire Lv3)
5. Final damage: 3 + 1 = 4

Key: Reuses damage proficiency system via IncreaseDamage(0)


EXAMPLE 3: WOOD SPELL WITH LV3 COST
------------------------------------
Scenario: Player with Wood Lv3 casts wood spell

Flow:
1. execute_spell_effect() extracts enchantments = [Wood]
2. BEFORE apply_effect(), applies Wood Lv3 special:
   player.hp -= 1
   player.shield += 1
3. Then apply other spell effects

Key: Wood Lv3 only proficiency applied in execute_spell_effect
Why: Cost must apply before healing effects resolve


EXAMPLE 4: WATER HEALING SPELL WITH LV5
----------------------------------------
Scenario: Player with Water Lv5 casts heal spell with Water requirement

Flow:
1. execute_spell_effect() extracts enchantments = [Water]
2. apply_effect() routes Heal to apply_heal_effect()
3. apply_heal_effect() loops through targets:
   if Water and target == caster: heal_amount += 1 (Lv3)
4. After loop, if Water and Lv5: team_member += 1 extra heal

Key: Different effect types trigger different proficiencies


EXAMPLE 5: FIRE LV5 PASSIVE
---------------------------
Scenario: Player's turn starts, they have Fire Lv5

Flow:
1. next_player() calls handle_turn_start()
2. handle_turn_start() checks: if player.fire >= 5
3. For each enemy: take_damage(1, DamageType::Skill)
4. Damage type is Skill, not Spell (doesn't get Wood Lv5 reduction)

Key: Passive proficiencies use different code paths


EXAMPLE 6: WOOD LV5 DAMAGE REDUCTION
-------------------------------------
Scenario: Player takes 10 spell damage, has Wood Lv5

Flow:
1. take_damage(10, DamageType::Spell) called
2. Checks: if DamageType::Spell and wood >= 5
3. damage = 10 - 1 = 9
4. If shield exists: shield absorbs 9 (or less if shield < 9)

Key: Defensive proficiencies apply in take_damage()


PROFICIENCY TRIGGER SUMMARY
============================

DAMAGE PROFICIENCIES:
- Triggered in apply_damage_effect()
- Matched by enchantments (attribute types)
- Applied as: base_damage += bonus
- Examples: Fire Lv3 (+1), Thunder Lv3/5 (+1/+3)

HEAL PROFICIENCIES:
- Triggered in apply_heal_effect()
- Matched by enchantments
- Applied as: heal_amount += bonus
- Examples: Water Lv3 (+1), Water Lv5 (team heal)

COST PROFICIENCIES:
- Wood Lv3: Triggered in execute_spell_effect()
- Applied BEFORE other effects
- Effect: -1 HP + 1 shield

PASSIVE PROFICIENCIES:
- Fire Lv5: Triggered in handle_turn_start()
- Wood Lv5: Triggered in player.take_damage()
- Wind/Poison: Triggered via buff system
- Not tied to spell casting

MULTI-ATTRIBUTE SPELLS:
- Spell with requirements [(Fire, 2), (Thunder, 2)]
- Both Fire and Thunder proficiencies can apply
- Example: 10 base + Fire Lv3 (+1) + Thunder Lv5 (+3) = 14


ENCHANTMENT FLOW
================

Spell Card Path:
spell.requirements -> extract attrs -> enchantments vector
                      -> apply_effect receives enchantments
                      -> handlers match enchantments to proficiencies

Attribute Bolt Path:
attr_type -> manually create -> enchantments = [attr_type]
             -> apply_effect receives enchantments
             -> handlers match (same as spell!)

Result: Both spells and bolts use identical proficiency matching


DAMAGE TYPE IMPACT
==================

Spell damage (DamageType::Spell):
- Reduced by Wood Lv5 (-1)
- Reduced by Guard Wood Carving (-4)
- Blocked by shields

Skill damage (DamageType::Skill):
- NOT reduced by Wood Lv5
- Reduced by Guard Wood Carving (-4)
- Blocked by shields

Direct damage (DamageType::Direct):
- Not reduced by anything
- Bypasses shields
- Used for costs like Wood Lv3 HP


KEY INSIGHTS
============

1. Enchantments are the central mechanism
   - Extracted from spell requirements
   - Passed through effect chain
   - Enable selective proficiency matching

2. Proficiencies are effect-type specific
   - Fire/Thunder only on damage
   - Water only on healing
   - Wood Lv3 on any spell cost

3. Passive proficiencies are independent
   - Fire Lv5 at turn start
   - Wood Lv5 during damage calculation
   - Not part of spell effect flow

4. Attribute bolts cleverly reuse spell system
   - Manual enchantment
   - IncreaseDamage(0) effect
   - Same proficiency handlers

5. Damage types separate offensive/defensive
   - Spell vs Skill affects Wood Lv5 reduction
   - Direct bypasses shields
   - Each has different proficiency rules
